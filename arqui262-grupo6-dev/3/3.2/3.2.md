# 3.2. Brainstorming de Escenarios

| ID | Stakeholder | Atributo de Calidad | Estímulo | Respuesta | Comentarios |
|----|-------------|---------------------|----------|-----------|-------------|
| ESCP-01 | STK-04 (Diseñador de Software) | Seguridad | Se expone la base de datos de credenciales de los usuarios | Las contraseñas no pueden recuperarse en texto plano y el acceso a los datos queda restringido | Protección de identidad y acceso |
| ESCP-02 | USR-01 (Viajero) | Seguridad | Un atacante realiza varios intentos fallidos de inicio de sesión | El sistema limita temporalmente los intentos y registra el evento | Protección contra ataques de fuerza bruta |
| ESCP-03 | USR-01 (Viajero) | Disponibilidad | El proveedor de autenticación con Google no responde durante el inicio de sesión | El sistema informa la falla y permite utilizar el inicio de sesión con correo y contraseña | Dependencia de un servicio externo |
| ESCP-04 | USR-01 (Viajero) | Usabilidad | Un viajero se registra y completa su perfil por primera vez desde un móvil | El sistema presenta campos claros, validaciones y mensajes que permiten completar el flujo | Incorporación de nuevos usuarios |
| ESCP-05 | STK-08 (Especialista en Despliegue) | Rendimiento | Aumenta la cantidad de usuarios que inician sesión simultáneamente | El sistema procesa los inicios de sesión sin degradar los demás módulos | Demanda durante temporadas altas |
| ESCP-06 | USR-01 (Viajero) | Rendimiento | Un viajero busca experiencias usando varios filtros | El sistema devuelve resultados ordenados y paginados dentro del tiempo esperado | Flujo central de descubrimiento |
| ESCP-07 | USR-01 (Viajero) | Usabilidad | Un viajero utiliza por primera vez los filtros de búsqueda | El sistema presenta criterios comprensibles y permite combinarlos para encontrar actividades compatibles con su itinerario | Reduce fricción en el descubrimiento |
| ESCP-08 | STK-03 (Jefe de Proyecto) | Disponibilidad | El módulo de disponibilidad no responde durante una búsqueda | El sistema muestra los datos de catálogo disponibles e indica que los horarios y cupos no pudieron verificarse | Degradación controlada del descubrimiento |
| ESCP-09 | STK-08 (Especialista en Despliegue) | Rendimiento | Miles de consultas de búsqueda se ejecutan simultáneamente | El sistema procesa y pagina las consultas sin rechazar solicitudes válidas | Requiere medición de carga |
| ESCP-10 | STK-09 (Responsable de Mantenimiento) | Mantenibilidad | Se necesita agregar un nuevo criterio de ordenamiento de recomendaciones | El equipo incorpora el criterio sin modificar la búsqueda ni los módulos propietarios de los datos | Evolución del MVP |
| ESCP-11 | STK-04 (Diseñador de Software) | Seguridad | Un operador intenta cargar una imagen con contenido malicioso en una experiencia | El sistema valida el archivo, bloquea contenido no permitido y registra el intento | Protección de usuarios y catálogo |
| ESCP-12 | USR-02 (Microoperador turístico) | Escalabilidad | Aumenta significativamente la cantidad de experiencias publicadas | El sistema mantiene la capacidad de filtrar y consultar el catálogo con tiempos estables | Crecimiento del catálogo |
| ESCP-13 | STK-08 (Especialista en Despliegue) | Disponibilidad | Una instancia del servicio de catálogo deja de responder | El sistema continúa atendiendo solicitudes mediante las instancias disponibles o informa una respuesta controlada | Continuidad de consultas |
| ESCP-14 | USR-01 (Viajero) | Confiabilidad | Varios viajeros intentan reservar simultáneamente los últimos cupos de una experiencia | El sistema confirma únicamente las reservas que caben en la capacidad disponible y rechaza las restantes | Evita la sobreventa |
| ESCP-15 | USR-01 (Viajero) | Rendimiento | Muchos viajeros consultan horarios y cupos para una fecha | El sistema devuelve las alternativas disponibles sin degradar el servicio | Consulta frecuente en temporada alta |
| ESCP-16 | STK-08 (Especialista en Despliegue) | Confiabilidad | Una solicitud de creación o confirmación de reserva se reenvía por un reintento de red | El sistema devuelve la reserva ya creada sin duplicarla ni descontar cupos otra vez | Idempotencia de operaciones |
| ESCP-17 | STK-05 (Administrador de Base de Datos) | Disponibilidad | La base de datos o una dependencia falla mientras se procesa una reserva | El sistema conserva un estado válido y trazable y permite recuperar o reintentar la operación | Evita confirmaciones parciales |
| ESCP-18 | USR-02 (Microoperador turístico) | Seguridad | Un usuario intenta modificar una reserva o disponibilidad que no le pertenece | El sistema verifica identidad, rol y propiedad del recurso y rechaza la acción no autorizada | Protección de recursos del operador |
| ESCP-19 | STK-03 (Jefe de Proyecto) | Escalabilidad | Las consultas y solicitudes de reserva aumentan hasta cinco veces la demanda normal | El sistema administra los recursos sin perder reservas ni exceder cupos | Crecimiento estacional |
| ESCP-20 | STK-09 (Responsable de Mantenimiento) | Mantenibilidad | Se modifica una regla de reserva, como el tiempo de bloqueo de cupos o las condiciones de cancelación | El cambio queda limitado al módulo de Reservas y sus contratos relacionados | Reduce regresiones en otros módulos |
| ESCP-21 | EXT-01 (Pasarela de pagos) | Disponibilidad | La pasarela externa deja de responder durante un pago | El sistema informa el estado conocido y evita confirmar una transacción sin respuesta verificable | Dependencia externa crítica |
| ESCP-22 | USR-01 (Viajero) | Confiabilidad | Se reenvía una solicitud de pago por timeout o pérdida de conexión | El sistema procesa la operación de forma idempotente y evita cobros duplicados | Integridad financiera |
| ESCP-23 | STK-04 (Diseñador de Software) | Seguridad | Un usuario intenta consultar o modificar datos de pago de otra persona | El sistema valida los permisos y rechaza el acceso no autorizado | Confidencialidad de datos financieros |
| ESCP-24 | STK-02 (Gestor del Negocio) | Mantenibilidad | La empresa decide cambiar o agregar una pasarela de pagos | El equipo sustituye o incorpora el adaptador sin cambiar el flujo central de reservas | Flexibilidad del negocio |
| ESCP-25 | USR-03 (Administrador de la plataforma) | Seguridad | Un usuario intenta publicar una reseña sin autenticarse | El sistema rechaza la solicitud hasta verificar la identidad | Autenticidad de reseñas |
| ESCP-26 | USR-01 (Viajero) | Seguridad | Un viajero intenta reseñar una experiencia sin una reserva completada asociada | El sistema verifica la reserva y rechaza la reseña no elegible | Previene manipulación de reputaciones |
| ESCP-27 | USR-01 (Viajero) | Rendimiento | Muchos viajeros consultan las valoraciones y reseñas de una experiencia | El sistema devuelve reputación y reseñas dentro del tiempo establecido | Consulta pública frecuente |
| ESCP-28 | USR-01 (Viajero) | Confiabilidad | Varios usuarios publican reseñas y calificaciones simultáneamente | El sistema registra cada reseña elegible sin pérdida ni duplicación y actualiza la valoración promedio | Consistencia de reputación |
| ESCP-29 | STK-08 (Especialista en Despliegue) | Disponibilidad | El servicio de reputación presenta una falla temporal | El sistema registra el error y permite recuperar el servicio sin afectar la consulta de experiencias | Recuperación de una dependencia |
| ESCP-30 | STK-09 (Responsable de Mantenimiento) | Mantenibilidad | Se requiere agregar un criterio de reputación u ordenar reseñas de otra forma | El equipo extiende las reglas sin modificar catálogo ni reservas | Evolución desacoplada |
| ESCP-31 | STK-04 (Diseñador de Software) | Interoperabilidad | Descubrimiento necesita combinar catálogo, disponibilidad y reputación | El sistema consulta las interfaces de los módulos propietarios y compone los resultados | Respeta los límites de cada módulo |
| ESCP-32 | STK-08 (Especialista en Despliegue) | Disponibilidad | La plataforma recibe una ráfaga de solicitudes automatizadas contra la búsqueda | El sistema limita la frecuencia abusiva y mantiene disponibles las solicitudes legítimas | Protección frente a saturación |
