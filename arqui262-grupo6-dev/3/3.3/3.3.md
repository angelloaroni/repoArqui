# 3.3. Consolidación de Escenarios

## 3.3.1. Módulo de Disponibilidad y Reservas

| Atributo       | Estímulo                                                                                                                                                                | Fuente                                    | Artefacto                                                                       | Entorno                                                | Respuesta                                                                                                                                                                                   | Medida de Respuesta                                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confiabilidad  | Múltiples usuarios intentan reservar simultáneamente los últimos cupos disponibles de una misma experiencia                                                             | Viajeros autenticados                     | Servicio de Reservas y almacenamiento de disponibilidad                         | Alta concurrencia con capacidad limitada               | El sistema procesa las reservas de forma atómica, confirma únicamente aquellas para las que existen cupos suficientes y rechaza las solicitudes restantes sin exceder la capacidad definida | 0 casos de sobreventa durante pruebas con al menos 100 solicitudes concurrentes sobre un mismo horario; reservas confirmadas ≤ capacidad disponible                       |
| Rendimiento    | Múltiples usuarios consultan simultáneamente la disponibilidad de experiencias para una fecha determinada                                                               | Viajeros utilizando la plataforma         | API y Servicio de Disponibilidad                                                | Operación normal con alta demanda                      | El sistema consulta horarios y cupos disponibles y devuelve las alternativas válidas sin degradación perceptible del servicio                                                               | 95% de consultas respondidas en ≤ 1.5 s bajo 100 solicitudes concurrentes; ninguna consulta superior a 3 s en condiciones normales                                        |
| Confiabilidad  | Una solicitud de creación o confirmación de reserva es enviada varias veces debido a un reintento o pérdida temporal de conexión                                        | Aplicación cliente / red externa          | API y Servicio de Reservas                                                      | Operación normal con fallos temporales de comunicación | El sistema identifica que la operación ya fue procesada y devuelve la reserva existente sin crear duplicados ni descontar nuevamente la capacidad                                           | Una misma operación genera exactamente 1 reserva y 1 modificación de capacidad, incluso ante múltiples reintentos                                                         |
| Disponibilidad | Ocurre una falla temporal en la base de datos o en una dependencia externa mientras una reserva está siendo procesada                                                   | Infraestructura / servicio externo        | Servicio de Reservas y almacenamiento persistente                               | Operación degradada durante una reserva en proceso     | El sistema evita dejar la reserva en un estado inconsistente, registra el fallo y permite reintentar o recuperar posteriormente la operación                                                | 100% de reservas afectadas mantienen un estado válido y trazable; máximo 3 reintentos automáticos; 0 reservas confirmadas parcialmente                                    |
| Seguridad      | Un usuario autenticado intenta consultar, modificar o cancelar una reserva perteneciente a otro usuario o modificar disponibilidad de una experiencia que no administra | Usuario autenticado sin autorización      | API de Reservas y Servicio de Autorización                                      | Operación normal                                       | El sistema valida identidad, rol y propiedad del recurso antes de ejecutar la operación y rechaza cualquier acción no autorizada                                                            | 100% de solicitudes no autorizadas rechazadas; 0 modificaciones persistentes realizadas por usuarios sin permisos                                                         |
| Escalabilidad  | La cantidad de consultas de disponibilidad y solicitudes de reserva aumenta significativamente durante un periodo de alta demanda                                       | Conjunto de usuarios de la plataforma     | API, Servicios de Disponibilidad y Reservas, pool de conexiones y base de datos | Carga elevada de hasta 5 veces la operación normal     | El sistema administra los recursos disponibles evitando que el aumento de consultas afecte la consistencia de las reservas o produzca una degradación crítica                               | Con una carga de hasta 5 veces la normal, 95% de consultas respondidas en ≤ 2 s; 0 reservas perdidas, duplicadas o con sobreventa                                         |
| Mantenibilidad | Se solicita modificar una regla de negocio de las reservas, como el tiempo de bloqueo de cupos, las condiciones de cancelación o los estados permitidos                 | Equipo de desarrollo / Gestor del Negocio | Lógica de dominio del Servicio de Reservas                                      | Mantenimiento y evolución del sistema                  | El sistema permite modificar la regla dentro del módulo de Reservas sin requerir cambios en módulos no relacionados como Usuarios, Catálogo o Descubrimiento                                | La modificación afecta únicamente al módulo de Reservas y a sus contratos directamente relacionados; pruebas de módulos no relacionados continúan funcionando sin cambios |

## 3.3.2. Consolidación de escenarios preliminares

| ID Escenario | Atributo de Calidad | Estímulo | Respuesta | ID Escenario Preliminar | Sustento | Comentarios |
|--------------|---------------------|-----------|------------|-------------------------|----------|-------------|
| CONS-01 | Seguridad | Se intenta acceder a cuentas, recursos o reseñas sin autorización, o se envía contenido malicioso | El sistema valida identidad, rol, propiedad del recurso y contenido antes de permitir la operación | ESCP-01, ESCP-02, ESCP-11, ESCP-18, ESCP-23, ESCP-25, ESCP-26 | Protege usuarios, datos, experiencias y reputación | Aplicable a varios módulos |
| CONS-02 | Disponibilidad | Falla temporalmente un proveedor o módulo requerido por autenticación, catálogo, reservas, pagos o reputación | El sistema responde de forma controlada, conserva estados válidos y permite recuperar o continuar las operaciones no dependientes | ESCP-03, ESCP-08, ESCP-13, ESCP-17, ESCP-21, ESCP-29, ESCP-32 | Mantiene la continuidad de los flujos principales | Las respuestas degradadas deben comunicar límites de información |
| CONS-03 | Usabilidad | Un viajero se registra, busca experiencias o aplica filtros por primera vez | La plataforma ofrece formularios, filtros y mensajes claros para completar la tarea | ESCP-04, ESCP-07 | Facilita la adopción y el descubrimiento de experiencias | Especialmente relevante en web móvil |
| CONS-04 | Rendimiento | Aumenta la concurrencia de inicios de sesión, búsquedas, consultas de disponibilidad y consultas de reputación | El sistema pagina y procesa las solicitudes dentro de los tiempos acordados | ESCP-05, ESCP-06, ESCP-09, ESCP-15, ESCP-27 | Afecta directamente la experiencia del viajero y del operador | Debe validarse mediante pruebas de carga |
| CONS-05 | Escalabilidad | Crecen el catálogo y el volumen de consultas y reservas | La plataforma escala sus recursos manteniendo tiempos de respuesta y consistencia de cupos | ESCP-12, ESCP-19 | Acompaña el crecimiento del negocio turístico | Considera temporadas de alta demanda |
| CONS-06 | Confiabilidad e integridad | Se reintenta una operación o concurren cambios sobre reservas, pagos o reseñas | El sistema evita duplicados, pérdida de datos, sobreventa y promedios inconsistentes | ESCP-14, ESCP-16, ESCP-22, ESCP-28 | Protege los datos y las operaciones críticas del negocio | Requiere operaciones idempotentes y consistentes |
| CONS-07 | Mantenibilidad | Se modifican reglas de reservas, recomendaciones, reputación o integración de pagos | El equipo cambia la funcionalidad afectada sin provocar regresiones en módulos no relacionados | ESCP-10, ESCP-20, ESCP-24, ESCP-30 | Facilita la evolución de la plataforma | Requiere contratos y pruebas entre módulos |
| CONS-08 | Interoperabilidad | Descubrimiento combina información de catálogo, disponibilidad y reputación | El sistema consume interfaces definidas por los módulos propietarios y presenta resultados integrados | ESCP-31 | Permite que los módulos colaboren conservando sus responsabilidades | La disponibilidad debe verificarse con su módulo propietario |
