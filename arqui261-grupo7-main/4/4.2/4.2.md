# 4.2. Módulo 2 / Integrante 2

# Decisión 1 (Asignación de Responsabilidades)

## Título:

Elección entre componente único, separación por componentes funcionales y microservicios para el módulo de Catálogo de Vehículos.

## Contexto

El módulo de Catálogo de Vehículos debe permitir el registro de vehículos, gestión de información descriptiva, administración de imágenes, actualización de disponibilidad y consultas de búsqueda dentro de la plataforma DriveShare.

Debido a que este módulo concentra la información principal que los usuarios utilizan para publicar y encontrar vehículos, es necesario organizar adecuadamente sus responsabilidades para facilitar el mantenimiento y permitir futuras ampliaciones de funcionalidades.

La necesidad principal es contar con una solución que permita gestionar eficientemente la información de los vehículos manteniendo una estructura organizada y fácil de evolucionar.

## Alternativas

| Alternativa                           | Descripción                                                                                               | Ventajas                                                              | Desventajas                                                    |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------- |
| Componente único                      | Toda la lógica del catálogo se implementa en un único componente.                                         | Implementación inicial sencilla y rápida.                             | Alto acoplamiento, difícil mantenimiento y baja escalabilidad. |
| Separación en componentes funcionales | El módulo se organiza en componentes especializados para vehículos, búsquedas, disponibilidad e imágenes. | Mejor organización, mantenibilidad y separación de responsabilidades. | Mayor esfuerzo inicial de diseño.                              |
| Microservicios independientes         | Cada funcionalidad se implementa como un servicio independiente.                                          | Alta escalabilidad y despliegue independiente.                        | Mayor complejidad de infraestructura y comunicación.           |

## Criterios de Elección

* Cohesión del sistema.
* Separación de responsabilidades.
* Mantenibilidad.
* Escalabilidad.
* Complejidad de la arquitectura.

## Decisión

Se decide implementar una separación en componentes funcionales dentro del módulo de Catálogo.

## Sustento

Esta alternativa permite mantener una correcta separación de responsabilidades entre la gestión de vehículos, disponibilidad, imágenes y búsquedas, facilitando la evolución del sistema y reduciendo el impacto de futuros cambios.

# Decisión 2 (Modelo de Coordinación)

## Título:

Elección de modelo de coordinación híbrido para el módulo de Catálogo de Vehículos.

## Contexto

El módulo debe gestionar operaciones de búsqueda de vehículos, consultas de disponibilidad y visualización de información por parte de los usuarios.

Algunas operaciones requieren respuestas inmediatas, mientras que otras actividades secundarias, como generación de estadísticas o procesamiento de imágenes, pueden ejecutarse en segundo plano.

## Alternativas

| Alternativa      | Descripción                                                              | Ventajas                                   | Desventajas                             |
| ---------------- | ------------------------------------------------------------------------ | ------------------------------------------ | --------------------------------------- |
| Modelo síncrono  | Todas las operaciones utilizan solicitudes REST con respuesta inmediata. | Fácil implementación y baja complejidad.   | Mayor dependencia entre componentes.    |
| Modelo asíncrono | Todas las operaciones utilizan eventos o colas de mensajes.              | Mayor desacoplamiento y escalabilidad.     | Incrementa la complejidad del sistema.  |
| Modelo híbrido   | Combina operaciones síncronas y asíncronas según el proceso.             | Balance entre simplicidad y escalabilidad. | Requiere definir claramente cada flujo. |

## Criterios de Elección

* Tiempo de respuesta.
* Escalabilidad.
* Complejidad de implementación.
* Experiencia de usuario.
* Mantenibilidad.

## Decisión

Se decide utilizar un modelo híbrido.

## Sustento

Las búsquedas y consultas de disponibilidad requieren respuesta inmediata mediante API REST, mientras que tareas como procesamiento de imágenes y generación de métricas pueden ejecutarse de manera asíncrona sin afectar la experiencia del usuario.

# Decisión 3 (Modelo de Datos)

## Título:

Elección de modelo híbrido PostgreSQL y Cassandra para el módulo de Catálogo.

## Contexto

El módulo debe almacenar información de vehículos, disponibilidad, imágenes e historial de búsquedas realizadas por los usuarios.

La información de los vehículos requiere consistencia e integridad, mientras que las búsquedas masivas requieren escalabilidad y alto rendimiento.

## Alternativas

| Alternativa    | Descripción                                                               | Ventajas                                          | Desventajas                                              |
| -------------- | ------------------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------- |
| PostgreSQL     | Toda la información se almacena en una base relacional.                   | Integridad, consistencia y soporte transaccional. | Menor escalabilidad para grandes volúmenes de consultas. |
| Cassandra      | Toda la información se almacena en una base NoSQL distribuida.            | Alta disponibilidad y escalabilidad horizontal.   | Menor soporte para relaciones complejas.                 |
| Modelo híbrido | PostgreSQL para datos transaccionales y Cassandra para consultas masivas. | Combina consistencia y escalabilidad.             | Mayor complejidad administrativa.                        |

## Criterios de Elección

* Integridad de datos.
* Rendimiento.
* Escalabilidad.
* Disponibilidad.
* Mantenibilidad.

## Decisión

Se decide utilizar un modelo híbrido basado en PostgreSQL y Cassandra.

## Sustento

PostgreSQL permitirá gestionar la información principal de los vehículos y disponibilidad, mientras que Cassandra permitirá almacenar historiales de búsqueda y consultas masivas, mejorando el rendimiento y la escalabilidad del catálogo.

# Decisión 4 (Gestión de Recursos)

## Título:

Decisión de almacenamiento distribuido de imágenes mediante MinIO.

## Contexto

El módulo de Catálogo permite que los propietarios publiquen vehículos acompañados de imágenes.

Estas imágenes pueden crecer considerablemente en volumen y afectar el rendimiento de la base de datos si se almacenan directamente en ella.

Por ello es necesario definir una estrategia eficiente para gestionar este recurso.

## Alternativas

| Alternativa                     | Descripción                                                         | Ventajas                                                | Desventajas                                                       |
| ------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------- |
| Almacenamiento en base de datos | Las imágenes se almacenan como BLOB dentro de PostgreSQL.           | Centraliza toda la información.                         | Incrementa el tamaño de la base de datos y afecta el rendimiento. |
| Sistema de archivos local       | Las imágenes se almacenan directamente en el servidor.              | Implementación sencilla.                                | Escalabilidad limitada y dependencia del servidor.                |
| MinIO                           | Las imágenes se almacenan en almacenamiento de objetos distribuido. | Alta escalabilidad, disponibilidad y mejor rendimiento. | Requiere infraestructura adicional.                               |

## Criterios de Elección

* Rendimiento.
* Escalabilidad.
* Disponibilidad.
* Facilidad de administración.
* Uso eficiente de recursos.

## Decisión

Se decide utilizar MinIO para el almacenamiento de imágenes.

## Sustento

MinIO permite gestionar grandes volúmenes de imágenes de manera eficiente, reduciendo la carga sobre la base de datos y facilitando la escalabilidad futura de la plataforma.

# Decisión 5 (Mapeo entre Elementos de Arquitectura)

## Título:

Elección de mapeo por capas entre elementos de arquitectura.

## Contexto

El sistema debe mantener separadas las responsabilidades relacionadas con la interfaz de usuario, lógica de negocio, persistencia e integración.

Esta separación facilita el mantenimiento y evolución del módulo.

## Alternativas

| Alternativa                               | Descripción                                                           | Ventajas                                     | Desventajas                                |
| ----------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------- | ------------------------------------------ |
| Mapeo directo                             | No existe separación clara entre componentes.                         | Simplicidad inicial.                         | Alto acoplamiento y difícil mantenimiento. |
| Mapeo por capas                           | Separación entre presentación, servicios, persistencia e integración. | Facilita mantenimiento, pruebas y evolución. | Requiere planificación inicial.            |
| Mapeo distribuido mediante microservicios | Cada funcionalidad se implementa como servicio independiente.         | Escalabilidad independiente.                 | Mayor complejidad operativa.               |

## Criterios de Elección

* Separación de responsabilidades.
* Organización del sistema.
* Facilidad de pruebas.
* Mantenibilidad.

## Decisión

Se decide utilizar un mapeo por capas.

## Sustento

El enfoque por capas permite organizar claramente la arquitectura del catálogo, reducir el acoplamiento y facilitar futuras modificaciones.

# Decisión 6 (Elección de Tecnología)

## Título:

FastAPI + PostgreSQL + Cassandra + MinIO + Docker

## Contexto

El módulo de Catálogo es responsable de la publicación, consulta y búsqueda de vehículos dentro de DriveShare.

Debe soportar búsquedas concurrentes, almacenamiento de imágenes y crecimiento continuo del volumen de información.

## Alternativas

| Alternativa                                       | Descripción                                                            | Ventajas                                        | Desventajas                               |
| ------------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------- | ----------------------------------------- |
| React + Express + PostgreSQL + Docker             | Stack JavaScript completo.                                             | Facilidad de desarrollo y amplia comunidad.     | Menor rendimiento para cargas intensivas. |
| FastAPI + PostgreSQL + Cassandra + MinIO + Docker | Backend Python con almacenamiento híbrido y almacenamiento de objetos. | Alto rendimiento, escalabilidad y flexibilidad. | Mayor complejidad operativa.              |
| Spring Boot + PostgreSQL + Elasticsearch + Docker | Solución empresarial basada en Java.                                   | Robustez y capacidad de búsqueda avanzada.      | Mayor curva de aprendizaje.               |

## Criterios de Elección

* Rendimiento.
* Escalabilidad.
* Disponibilidad.
* Mantenibilidad.
* Facilidad de integración.

## Decisión

Se selecciona FastAPI + PostgreSQL + Cassandra + MinIO + Docker para el módulo de Catálogo.

## Sustento

FastAPI proporciona alto rendimiento y soporte para operaciones concurrentes. PostgreSQL garantiza integridad en la información de los vehículos, Cassandra mejora el rendimiento de consultas masivas, MinIO facilita el almacenamiento distribuido de imágenes y Docker simplifica el despliegue y operación de la solución.
