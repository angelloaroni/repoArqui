# 9.4.4. Elementos instanciados

Las tácticas seleccionadas se instancian sobre los componentes existentes de la siguiente manera:

## Instanciación para CONS-09 — Disponibilidad (Reservas)

| Elemento refinado | Instanciación concreta |
|---|---|
| `ReservationService` | Antes de crear o modificar una reserva, consulta solapamientos activos (`Pendiente` / `Confirmada`) sobre el mismo `vehicle_id` y rango de fechas; responde conflicto (HTTP 409) si existe traslape. |
| `ReservationService.confirm` | Revalida disponibilidad al confirmar tras el pago; evita confirmar una reserva Pendiente si el vehículo ya fue ocupado por otra reserva concurrente. |
| `ReservationRepository.findOverlapping` | Consulta Sequelize con condiciones de rango (`start_date < fin` y `end_date > inicio`) filtrando solo estados que bloquean disponibilidad. |
| `GET /api/reservations/availability/:vehicleId` | Endpoint público de verificación puntual de disponibilidad para un vehículo y fechas. |
| `GET /api/reservations/unavailable` | Endpoint que retorna los `vehicle_id` no disponibles en un rango, usado por el catálogo para filtrar “Solo disponibles”. |
| Transacción Sequelize al crear | La creación de la reserva se ejecuta dentro de una transacción: ante error se hace *rollback* y no queda estado parcial en `RESERVATION`. |
| Modelo / tabla `RESERVATION` | Persistencia del ciclo de vida (`Pendiente`, `Confirmada`, `Cancelada`, `Rechazada`, `Finalizada`); solo estados activos bloquean fechas. |
| Frontend de catálogo / detalle | Consulta disponibilidad por fechas antes de ofrecer o confirmar la intención de reserva, reduciendo intentos inválidos. |

## Instanciación para CONS-01 — Seguridad (Usuarios y acceso)

| Elemento refinado | Instanciación concreta |
|---|---|
| `AuthMiddleware` | Valida el JWT del header `Authorization: Bearer` en rutas protegidas; responde HTTP 401 ante token ausente, inválido o expirado. |
| `RateLimitMiddleware` | Limita intentos en endpoints sensibles (`/login`, `/registrar`, recuperación de contraseña) para mitigar fuerza bruta. |
| `UsuarioService` | Hash de contraseñas con bcrypt; registro, verificación de cuenta y recuperación con códigos temporales; emisión de JWT con `id_user`, `email` y `role`. |
| Rutas de usuarios / reservas | Operaciones de perfil, reservas y gestión del propietario requieren autenticación; autorización por dueño/rol en acciones de reserva (arrendatario vs propietario). |
| `ProtectedRoute` / `RoleRoute` / `UserContext` | En el Frontend, restringen pantallas de reserva, pago y panel de arrendador según sesión y rol. |
| `AuditService` + `AUDIT_LOG` | El Sidecar registra eventos relevantes (login, registro, cambios de cuenta y acciones de reserva) de forma desacoplada del Backend principal. |
| Vault / cifrado RSA (donde aplique) | Secretos y datos sensibles (p. ej. documento, teléfono, licencia) se gestionan fuera de texto plano. |
