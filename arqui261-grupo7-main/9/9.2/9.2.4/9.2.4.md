# 9.2.4. Elementos instanciados

Al instanciar los conceptos de diseño seleccionados durante la primera iteración del proceso ADD, la arquitectura de DriveShare queda organizada en un conjunto de contenedores que agrupan las responsabilidades del sistema y permiten el desarrollo independiente de cada módulo funcional.

---

## Contenedores instanciados

| Elemento instanciado | Concepto que instancia | Tecnología | Responsabilidad asignada |
|----------------------|------------------------|------------|--------------------------|
| **Aplicación Web** | Cliente (Cliente-Servidor), Tier Cliente | React + Vite | Presentar la interfaz gráfica del sistema, gestionar la navegación entre módulos y consumir la API REST del backend. |
| **API REST** | Servidor (Cliente-Servidor), Arquitectura en Capas, Tier Aplicación | Node.js + Express | Centralizar la lógica de negocio, validar las solicitudes, aplicar autenticación y exponer los servicios REST de los cinco módulos. |
| **Base de Datos** | Datos Compartidos, Tier Datos | PostgreSQL | Almacenar de forma persistente la información de usuarios, vehículos, reservas, pagos y reseñas garantizando integridad y consistencia. |
| **Storage Component** | Servicio de almacenamiento | MinIO | Gestionar el almacenamiento de las imágenes asociadas a los vehículos publicados en el catálogo. |
| **Cache Component** | Componente de soporte | Redis (Cache Component) | Mejorar el rendimiento almacenando temporalmente consultas frecuentes y datos utilizados por distintos módulos del sistema. |
| **Search Database** | Servicio de búsqueda | Search Database | Optimizar la búsqueda y filtrado de vehículos disponibles dentro del catálogo. |

---

# Elementos transversales instanciados

| Elemento | Ubicación | Responsabilidad |
|-----------|-----------|-----------------|
| **JWT Middleware** | API REST | Validar el token de autenticación antes de acceder a los servicios protegidos. |
| **Authorization Middleware** | API REST | Verificar los permisos del usuario según el rol (Administrador, Arrendador o Arrendatario). |
| **Storage Component (MinIO)** | Infraestructura | Almacenar y recuperar las imágenes publicadas por los propietarios de vehículos. |
| **Cache Component** | Backend | Reducir los tiempos de respuesta almacenando temporalmente consultas frecuentes del sistema. |
| **Search Database** | Backend | Indexar la información del catálogo para acelerar las búsquedas y los filtros avanzados de vehículos. |
| **Database Connection Pool** | Backend | Administrar las conexiones compartidas hacia PostgreSQL utilizadas por todos los módulos. |

---

Los elementos instanciados representan la primera descomposición arquitectónica de DriveShare. Cada módulo funcional queda asignado a un conjunto de componentes específicos dentro de la arquitectura general, permitiendo que el desarrollo se realice de manera independiente y manteniendo una comunicación uniforme mediante servicios REST sobre una arquitectura Cliente-Servidor organizada por capas y desplegada bajo el patrón Multi-Tier.
