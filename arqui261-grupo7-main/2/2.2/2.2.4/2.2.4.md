# 2.2.4. Módulo 4 / Integrante 4

## Modulo de pago


### Requisitos de Atributos de Calidad
| Atributo de Calidad | Estímulo | Fuente del Estímulo | Artefacto | Entorno | Respuesta | Medida de Respuesta |
| --- | --- | --- | --- | --- | --- | --- |
| Rendimiento | Varios usuarios completan el pago de forma simultánea | Usuarios | Módulo de Pagos – endpoint de cobro | Alta demanda (feriados o temporada alta) | El sistema encola y procesa las solicitudes sin rechazar peticiones | El tiempo de respuesta no supera los 10 s por transacción; tasa de error menor al 0.5 % |
| Seguridad | Alguien intenta pagar con una tarjeta robada | Usuario malintencionado | Módulo de Pagos – validación | Cualquier momento del día | El sistema detecta que la tarjeta es sospechosa, bloquea el pago y avisa al administrador | El 100 % de pagos fraudulentos son bloqueados antes de procesarse |
| Mantenibilidad | Cambio de proveedor de pagos | Decisión de negocio | Módulo de Integración con Gateway de Pago | Sprint de mantenimiento | El sistema permite reemplazar el adaptador del proveedor sin modificar la lógica de cobros | El cambio se realiza en un máximo de 3 días hábiles |
| Seguridad | Acceso no autorizado a los datos de tarjetas almacenadas | Atacante interno o externo | Módulo de Almacenamiento de Métodos de Pago | Operación normal | El sistema protege los datos mediante tokenización, bloquea el acceso no autorizado y registra el intento | No se expone ningún número de tarjeta y se genera una alerta en menos de 2 segundos |
| Disponibilidad | Caída de la base de datos de transacciones | Infraestructura en la nube | Módulo de Historial de Pagos | Alta demanda durante fin de semana largo | El sistema activa una réplica para lecturas y encola las escrituras hasta que el servicio se restaure | El servicio se recupera en menos de 30 segundos sin pérdida de datos |
| Disponibilidad | El gateway de pago externo no responde | Proveedor de pagos | Módulo de Pagos - gateway externo | Operación normal | El sistema muestra un mensaje de error al usuario e indica que puede reintentar más tarde | El usuario recibe la notificación en menos de 5 segundos y no se genera ningún cobro |
| Mantenibilidad | Incorporación de un nuevo método de pago | Equipo de desarrollo | Módulo de Métodos de Pago | Sprint de desarrollo iterativo | El sistema permite agregar el nuevo método sin modificar el flujo de pago existente | El cambio se implementa en un máximo de 5 días sin afectar los métodos ya disponibles |
