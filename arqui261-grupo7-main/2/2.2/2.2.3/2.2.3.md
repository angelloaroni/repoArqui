# 2.2.3. Módulo 3 / Integrante 3

| Atributo | Estímulo | Fuente | Artefacto | Entorno | Respuesta | Medida de Respuesta |
|-----------------|--------------------------------------------------------------------------|-----------------------------------------------------|---------------------------------------------|-------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------|
| Disponibilidad | Dos usuarios intentan reservar el mismo vehículo para las mismas fechas simultáneamente | Arrendatarios concurrentes | Módulo de Reservas | Operación normal | El sistema bloquea temporalmente la disponibilidad del vehículo mientras procesa la primera solicitud válida y evita reservas duplicadas | 0 reservas duplicadas registradas; validación completada en ≤ 3 s |
| Rendimiento | 500 usuarios realizan búsquedas de vehículos disponibles simultáneamente durante hora pico | Usuarios arrendatarios | Servicio de Búsqueda y Reservas | Alta demanda | El sistema responde las consultas de disponibilidad y filtros sin degradación perceptible | Tiempo de respuesta de búsqueda ≤ 5 s con 500 usuarios concurrentes |
| Seguridad | Un usuario intenta modificar o cancelar una reserva que no le pertenece | Usuario malintencionado autenticado | API de Gestión de Reservas | Operación normal | El sistema valida los permisos del usuario y rechaza la operación no autorizada | 100% de intentos no autorizados bloqueados; respuesta de denegación en ≤ 2 s |
| Disponibilidad | El servicio de pagos demora en confirmar una transacción asociada a una reserva | Servicio externo de pagos | Flujo de Confirmación de Reserva | Alta demanda | El sistema mantiene la reserva en estado pendiente hasta recibir la confirmación del pago y notifica al usuario sobre el estado del proceso | Estado actualizado en ≤ 10 s después de recibir respuesta del servicio de pagos |
| Usabilidad | Un usuario desea modificar las fechas de una reserva antes del inicio del alquiler | Arrendatario | Interfaz de Gestión de Reservas | Operación normal desde dispositivo móvil | El sistema permite modificar las fechas disponibles mediante una interfaz intuitiva mostrando conflictos y costos actualizados en tiempo real | Modificación completada en ≤ 3 min; tasa de error de usuario ≤ 10% |
| Fiabilidad | Ocurre una caída del sistema durante el proceso de creación de una reserva | Fallo interno del servidor | Servicio de Reservas | Operación anormal | El sistema conserva el estado de la transacción y evita pérdida o duplicación de reservas al restaurarse el servicio | 100% de integridad de datos recuperada; recuperación del servicio en ≤ 5 min |
| Escalabilidad | El número de reservas activas aumenta significativamente durante temporadas festivas | Incremento masivo de usuarios | Infraestructura del Módulo de Reservas | Alta demanda | El sistema distribuye la carga automáticamente para mantener la estabilidad del servicio | Soporte de hasta 5,000 reservas concurrentes sin caída del sistema |
| Disponibilidad | Un propietario rechaza una solicitud de reserva | Propietario del vehículo | Gestión de Reservas del Propietario | Operación normal | El sistema actualiza inmediatamente el estado de la reserva y libera nuevamente las fechas del vehículo | Actualización reflejada en ≤ 5 s; disponibilidad sincronizada en tiempo real |
