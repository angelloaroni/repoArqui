# 0.7.2. Integrante 2

# Desarrollo Conceptual: NoSQL – Bases de Datos Columnares

## Definición
Las bases de datos **NoSQL columnares** son sistemas que organizan la información por columnas en lugar de filas completas. Este modelo permite consultas rápidas sobre atributos específicos, gran flexibilidad en el esquema y escalabilidad horizontal en clústeres distribuidos. Son ideales para aplicaciones que manejan grandes volúmenes de datos heterogéneos.

---

## 🔑 Características principales
- **Modelo flexible**: no requiere un esquema rígido, se pueden añadir columnas sin afectar las demás filas.  
- **Almacenamiento por columnas**: los valores de cada atributo se guardan contiguos en disco, optimizando consultas sobre campos específicos.  
- **Escalabilidad horizontal**: se distribuye la información en múltiples nodos del clúster.  
- **Alta disponibilidad**: los datos se replican en varios nodos, evitando puntos únicos de falla.  
- **Consistencia eventual**: prioriza disponibilidad y rendimiento sobre consistencia estricta.  

---

## 📋 Capas conceptuales
Podemos organizar el concepto en niveles:

| **Capa**            | **Descripción**                                                   | **Ejemplos**                  |
|----------------------|-------------------------------------------------------------------|-------------------------------|
| **Modelo de datos**  | Organización en columnas dinámicas, cada fila puede tener atributos distintos. | Cassandra, HBase              |
| **Almacenamiento**   | Valores de cada columna se guardan juntos en disco.               | Lecturas rápidas de atributos |
| **Procesamiento**    | Consultas optimizadas para grandes volúmenes y atributos concretos. | SELECT marca, precio          |
| **Aplicación**       | Sistemas que consumen datos flexibles y escalables.               | Catálogo de vehículos, logs   |

---

## 📊 Comparación conceptual
| **Aspecto**        | **SQL Relacional**                  | **NoSQL Columnares**                  |
|---------------------|-------------------------------------|---------------------------------------|
| Esquema             | Rígido, requiere ALTER TABLE        | Flexible, columnas dinámicas           |
| Almacenamiento      | Por filas completas                 | Por columnas                           |
| Escalabilidad       | Vertical (más CPU/RAM)              | Horizontal (más nodos)                 |
| Consistencia        | ACID                                | BASE (consistencia eventual)           |
| Ejemplo aplicado    | Tabla `vehiculos` con columnas fijas | Tabla `vehiculos` en Cassandra con columnas opcionales |

---

## 🚗 Ejemplo aplicado a tu proyecto
En tu **catálogo de vehículos**, Cassandra guarda cada atributo (marca, modelo, año, precio) en bloques de columnas.  
- Si consultas solo `marca` y `precio`, Cassandra accede directamente a esas columnas sin recorrer toda la fila.  
- Esto hace que tu sistema sea más eficiente para búsquedas rápidas y escalable si el catálogo crece a miles de registros.  

---

## 🎯 Conclusión
Las bases de datos NoSQL columnares representan una evolución frente al modelo relacional, ofreciendo **flexibilidad, escalabilidad y eficiencia en consultas específicas**. Son ideales para aplicaciones modernas como catálogos, sistemas de telemetría, analítica de grandes volúmenes y plataformas distribuidas.

# Demo (código)

En este escenario se simula la **búsqueda y reserva de un vehículo** dentro de la plataforma.  
El **Catálogo de Vehículos** (Módulo 2) almacena la información en una base de datos **NoSQL columnar (Cassandra)**, lo que permite consultas rápidas y flexibles.

### Flujo de uso
1. El arrendador registra un **Kia Sportage 2026** con precio de 90.0.  
2. El arrendatario ingresa al catálogo y aplica filtros por **marca** y **precio**.  
3. Cassandra devuelve solo las columnas necesarias (`marca`, `precio`), optimizando la consulta.  
4. El usuario visualiza el vehículo disponible y procede a la reserva.  

### Beneficio
El modelo columnar permite que el catálogo escale fácilmente a cientos de vehículos, manteniendo la **rapidez en las búsquedas** y la **flexibilidad en el esquema de datos**.

Repositorio codigo: https://github.com/luismiguel2017/modulo2-catalogo

- app.py
   ```python
    from flask import Flask, render_template, request, redirect
  from cassandra.cluster import Cluster
  from uuid import uuid4
  
  app = Flask(__name__)
  
  # Conexión a Cassandra
  cluster = Cluster(['127.0.0.1'])
  session = cluster.connect('catalogo')
  
  # Crear tabla si no existe
  session.execute("""
      CREATE TABLE IF NOT EXISTS vehiculos (
          id UUID PRIMARY KEY,
          marca text,
          modelo text,
          anio int,
          precio double
      )
  """)
  
  @app.route('/')
  def index():
      rows = session.execute("SELECT * FROM vehiculos")
      vehiculos = []
      for row in rows:
          vehiculos.append({
              'id': row.id,  # importante para eliminar
              'marca': row.marca,
              'modelo': row.modelo,
              'anio': row.anio,
              'precio': row.precio
          })
      return render_template('catalogo.html', vehiculos=vehiculos)
  
  @app.route('/insertar', methods=['POST'])
  def insertar():
      marca = request.form['marca']
      modelo = request.form['modelo']
      anio = int(request.form['anio'])
      precio = float(request.form['precio'])

    session.execute("""
        INSERT INTO vehiculos (id, marca, modelo, anio, precio)
        VALUES (%s, %s, %s, %s, %s)
    """, (uuid4(), marca, modelo, anio, precio))

    return redirect('/')
    
    @app.route('/buscar')
    def buscar():
        q = request.args.get('q', '').lower()
        rows = session.execute("SELECT * FROM vehiculos")
        vehiculos = []
        for row in rows:
            if q in row.marca.lower() or q in row.modelo.lower():
                vehiculos.append({
                    'id': row.id,
                    'marca': row.marca,
                    'modelo': row.modelo,
                    'anio': row.anio,
                    'precio': row.precio
                })
        return render_template('catalogo.html', vehiculos=vehiculos)
    
    @app.route('/eliminar/<uuid:vehiculo_id>', methods=['POST'])
    def eliminar(vehiculo_id):
        session.execute("DELETE FROM vehiculos WHERE id = %s", (vehiculo_id,))
        return redirect('/')
    
    if __name__ == '__main__':
        app.run(debug=True)
