# 0.9.2. Integrante 2

# Análisis de Seguridad de APIs

## Desarrollo Conceptual

### 1. Definición

El análisis de seguridad de APIs consiste en evaluar los mecanismos de protección implementados en una Interfaz de Programación de Aplicaciones (API) para garantizar la confidencialidad, integridad y disponibilidad de la información que procesa. Su objetivo es identificar vulnerabilidades que puedan ser explotadas por usuarios maliciosos y verificar que la API implemente controles adecuados de autenticación, autorización, validación de datos, protección de comunicaciones y manejo de errores.

En arquitecturas modernas basadas en microservicios, las APIs representan el principal punto de interacción entre aplicaciones cliente y servicios backend, convirtiéndose en uno de los componentes más críticos desde el punto de vista de la seguridad. Por ello, el análisis de seguridad debe realizarse desde las primeras etapas del desarrollo y mantenerse durante todo el ciclo de vida de la aplicación.

En el **Módulo 2 de DriveShare**, la API desarrollada con **FastAPI** expone servicios para la administración del catálogo de vehículos, incluyendo el registro, consulta, actualización, eliminación, carga de imágenes y gestión de disponibilidad. Estas operaciones requieren mecanismos de seguridad que impidan accesos no autorizados y protejan la información almacenada.

---

## 2. Problema que Resuelve

Cuando una API se expone sin controles adecuados, aparecen diversos riesgos de seguridad que pueden comprometer tanto la información de los usuarios como la continuidad del servicio.

Entre los principales problemas se encuentran:

- Acceso no autorizado a recursos protegidos.
- Manipulación de información mediante solicitudes maliciosas.
- Exposición de información sensible en las respuestas del servidor.
- Ataques de fuerza bruta contra los endpoints de autenticación.
- Inyección de código mediante parámetros no validados.
- Consumo excesivo de recursos mediante ataques de denegación de servicio (DoS).

El análisis de seguridad permite identificar estos riesgos antes de que la aplicación sea puesta en producción, fortaleciendo la protección del sistema y reduciendo la probabilidad de incidentes de seguridad.

---

## 3. Conceptos Clave

### 3.1 Autenticación

La autenticación verifica la identidad del usuario que intenta acceder a la API. Generalmente se implementa mediante mecanismos como OAuth 2.0, JWT (JSON Web Tokens), API Keys o autenticación basada en sesiones.

En DriveShare, el **Módulo 1** administra la autenticación de usuarios, mientras que el **Módulo 2** utiliza dicha identidad para determinar qué operaciones puede realizar cada propietario sobre sus vehículos.

---

### 3.2 Autorización

La autorización determina qué acciones puede ejecutar un usuario autenticado sobre los recursos del sistema.

Por ejemplo:

- Un propietario puede registrar, modificar y eliminar únicamente sus propios vehículos.
- Un arrendatario puede consultar el catálogo y realizar reservas.
- Un administrador posee permisos para gestionar todos los recursos.

La correcta implementación de controles de autorización evita vulnerabilidades como **Broken Access Control**, considerada una de las principales amenazas según OWASP.

---

### 3.3 Validación de Entradas

Toda información recibida por la API debe validarse antes de ser procesada.

La validación incluye:

- Tipo de dato.
- Longitud máxima.
- Formato.
- Valores permitidos.
- Campos obligatorios.

En el Módulo 2 esta validación se implementa mediante **Pydantic**, garantizando que únicamente se procesen datos válidos y reduciendo el riesgo de ataques por inyección.

---

### 3.4 Comunicación Segura

La comunicación entre cliente y servidor debe realizarse utilizando protocolos seguros como HTTPS/TLS.

El uso de conexiones cifradas protege la información frente a:

- Ataques Man in the Middle (MITM).
- Robo de credenciales.
- Alteración de datos durante la transmisión.

Durante el desarrollo local se utiliza HTTP; sin embargo, en producción debe emplearse HTTPS.

---

### 3.5 Gestión de Errores

Las respuestas de error deben proporcionar únicamente la información necesaria para el cliente, evitando revelar detalles internos del sistema.

No deben exponerse:

- Consultas SQL.
- Rutas del servidor.
- Stack Trace.
- Información de configuración.
- Credenciales.

FastAPI permite controlar estas respuestas mediante excepciones personalizadas utilizando `HTTPException`.

---

### 3.6 Rate Limiting

El Rate Limiting restringe el número de solicitudes que un cliente puede realizar durante un intervalo determinado.

Su objetivo es proteger la API frente a:

- Ataques de fuerza bruta.
- Ataques de denegación de servicio.
- Automatización maliciosa.
- Consumo excesivo de recursos.

En el Módulo 2 se configuró el siguiente límite:

```text
RATE_LIMIT=20/minute
```

---

## 4. Principios Subyacentes

El análisis de seguridad de APIs se basa en principios ampliamente utilizados dentro de la ingeniería de software y la ciberseguridad.

### Principio del Menor Privilegio

Cada usuario únicamente debe disponer de los permisos estrictamente necesarios para realizar sus funciones.

---

### Defensa en Profundidad

La seguridad no debe depender de un único mecanismo, sino de múltiples capas de protección.

En el Módulo 2 se aplican:

- Autenticación.
- Autorización.
- Validación de datos.
- HTTPS.
- Rate Limiting.
- Manejo de errores.

---

### Validación de Datos

Toda entrada proveniente del exterior debe considerarse potencialmente maliciosa hasta ser validada correctamente.

---

### Seguridad por Diseño

Los controles de seguridad deben incorporarse desde el diseño de la aplicación y mantenerse durante todo su ciclo de vida.

---

## 5. Controles Aplicados en el Módulo 2

| Control | Implementación |
|----------|----------------|
| Validación de datos | Pydantic Schemas |
| ORM seguro | SQLAlchemy |
| Protección contra SQL Injection | Consultas parametrizadas mediante SQLAlchemy |
| Comunicación entre servicios | API REST |
| Almacenamiento de imágenes | MinIO |
| Manejo de errores | HTTPException |
| Restricción de solicitudes | Rate Limiting |
| Framework | FastAPI |

---

## 6. Relación con Estándares Internacionales

El análisis de seguridad de APIs se encuentra alineado con diversos estándares y marcos de referencia:

- OWASP API Security Top 10.
- OWASP ASVS (Application Security Verification Standard).
- NIST SP 800-204A.
- ISO/IEC 27001.
- CWE (Common Weakness Enumeration).

Estos estándares proporcionan recomendaciones para identificar vulnerabilidades, implementar controles de seguridad y evaluar el nivel de protección de una API.

---

## 7. Beneficios y Costos

### Beneficios

- Protección frente a ataques dirigidos a APIs.
- Reducción del riesgo de accesos no autorizados.
- Mayor confiabilidad del sistema.
- Cumplimiento de buenas prácticas internacionales.
- Facilita auditorías de seguridad.
- Mayor protección de la información de los usuarios.

---

### Costos

- Incremento en el tiempo de desarrollo debido a la implementación de controles de seguridad.
- Mayor complejidad en la gestión de autenticación y autorización.
- Necesidad de realizar pruebas de seguridad de forma continua.
- Mantenimiento permanente para actualizar dependencias y corregir vulnerabilidades.
