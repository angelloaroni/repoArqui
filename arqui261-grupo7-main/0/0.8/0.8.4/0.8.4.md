# 0.8.4. Integrante 4

# Compensating Transaction pattern

## Desarrollo

### **Problema:** 
En sistemas distribuidos, una sola operación de negocio puede involucrar varios servicios independientes, cada uno con su propia base de datos. El problema surge cuando uno de los pasos del medio falla: los pasos anteriores ya se ejecutaron y no existe un `ROLLBACK` global que los deshaga. Usar protocolos como *Two-Phase Commit* (2PC) tampoco es viable a escala, ya que bloquean recursos mientras esperan confirmación de todos los participantes, un cuello de botella crítico en sistemas de alta concurrencia.

Lo que complica aún más el problema es que "deshacer" un paso no siempre es tan simple como borrar un registro. Si ya se cobró una tarjeta, hay que emitir un reembolso real. Si ya se notificó a un usuario, hay que enviar otra notificación. Cada deshacimiento puede requerir llamadas a servicios externos, aplicar reglas de negocio propias, o incluso intervención humana.

### **Solución:** 
El patrón propone implementar una transacción de compensación, es decir, un conjunto de acciones diseñadas específicamente para deshacer o neutralizar los efectos de las operaciones que se completaron exitosamente antes de que ocurriera el fallo. Cada paso de la operación principal tiene asociada una acción compensatoria que se ejecuta cuando no es posible continuar el flujo normal. Estas acciones no necesariamente restauran el estado original exacto, sino que aplican reglas de negocio para llevar el sistema a un estado consistente y válido. Generalmente, un orquestador o flujo de trabajo registra cada operación realizada y la forma de revertirla, permitiendo ejecutar las compensaciones de manera controlada, incluso en paralelo o en un orden diferente al de la ejecución original. Además, las acciones de compensación deben ser idempotentes para soportar reintentos y garantizar la recuperación ante errores.

### **Casos de Aplicación:** 

1. Comercio Electrónico (E-commerce):  
    Empresas como Amazon o tiendas en línea utilizan este patrón cuando una compra involucra varios pasos: crear el pedido, descontar stock y procesar el pago. Si el pago falla, el sistema debe restaurar el stock y cancelar el pedido para evitar inconsistencias.

2. Plataformas de Reservas de Viajes y Alojamiento:  
    Plataformas como Booking.com o Expedia gestionan reservas de vuelos, hoteles y transporte. Si la reserva del hotel falla después de confirmar el vuelo, se pueden cancelar las reservas previas o buscar alternativas antes de completar la transacción.

3. Marketplaces y Plataformas de Pago:  
    En plataformas que integran pasarelas como Culqi, PayPal o Stripe, el patrón permite revertir pedidos, liberar inventario o cancelar servicios cuando un cobro es rechazado o presenta errores.
