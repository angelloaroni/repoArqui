# 7.1. Catálogo de Aplicaciones

El sistema DriveShare se compone de una aplicación web para los usuarios, una API REST para la gestión de la lógica de negocio principal y un microservicio independiente para el procesamiento de pagos. Las aplicaciones se comunican mediante peticiones HTTP/HTTPS y mensajería asíncrona siguiendo la arquitectura definida en la sección 6.2.

---

## APP-01: Aplicación Web (Frontend)

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-frontend` |
| **Tipo** | Single Page Application (SPA) |
| **Tecnología** | React + Vite + Tailwind CSS |
| **Puerto de desarrollo** | 5173 |
| **Responsabilidad** | Proporciona la interfaz para arrendadores y arrendatarios. Gestiona la navegación, autenticación, visualización de vehículos, reservas, pagos y reseñas de la plataforma. |
| **Comunicación** | Consume la API REST y el Servicio de Pagos mediante peticiones HTTP/HTTPS. La autenticación se realiza mediante JWT almacenado en cookies HttpOnly, por lo que el frontend no accede ni administra directamente el token. |
| **Módulos cubiertos** | Autenticación, Gestión de Usuarios, Gestión de Vehículos, Reservas, Pagos y Reseñas. |

**Estructura de directorios:**

```text
driveshare-frontend/
├── public/
├── src/
│   ├── assets/             # Imágenes, logos e iconos
│   ├── components/         # Componentes reutilizables de la interfaz
│   ├── context/            # Estado global y contexto de usuario
│   ├── views/              # Vistas y pantallas principales
│   └── main.jsx            # Punto de entrada de la aplicación
├── index.html
├── Dockerfile
├── vite.config.js
└── package.json
```

## APP-02: API REST (Backend Principal)

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-backend` |
| **Tipo** | API REST |
| **Tecnología** | Node.js + Express + Sequelize |
| **Puerto de desarrollo** | 3000 |
| **Responsabilidad** | Punto central de la lógica de negocio. Gestiona la autenticación mediante JWT y ejecuta las operaciones relacionadas con usuarios, vehículos, reservas y reseñas. Coordina la persistencia de datos en PostgreSQL y Cassandra, y administra la comunicación con servicios externos. |
| **Comunicación** | Recibe solicitudes HTTP/HTTPS desde la aplicación web. Utiliza PostgreSQL como mecanismo principal de persistencia mediante Sequelize, y Cassandra para consultas masivas e historial de búsquedas. Integra servicios externos para autenticación (Google OAuth), almacenamiento de imágenes (MinIO), notificaciones por correo (Resend) y gestión segura de secretos (HashiCorp Vault). Publica eventos de reserva en RabbitMQ. |
| **Módulos cubiertos** | Gestión de Usuarios, Gestión de Vehículos, Gestión de Reservas, Gestión de Reseñas, Autenticación y Autorización. |

**Estructura de directorios:**
```text
driveshare-backend/
├── src/
│   ├── routes/                # Endpoints REST para usuarios, vehículos, reservas y reseñas
│   ├── controllers/           # Recepción y procesamiento de solicitudes HTTP
│   ├── services/              # Lógica de negocio de los módulos del sistema
│   ├── repositories/          # Acceso y persistencia de datos en PostgreSQL y Cassandra
│   ├── models/                # Modelos y entidades gestionadas mediante Sequelize
│   ├── integrations/          # Integración con servicios externos
│   │   ├── googleOAuth/       # Integración con autenticación Google OAuth
│   │   ├── minio/             # Gestión de almacenamiento de imágenes
│   │   ├── resend/            # Envío de correos electrónicos
│   │   └── vault/             # Gestión de secretos mediante HashiCorp Vault
│   ├── middlewares/           # Validación de JWT y lógica transversal
│   ├── config/                # Configuración de la aplicación y conexiones
│   └── tests/                 # Pruebas unitarias e integración
│
├── init/
│   └── init-vault.js          # Carga inicial de claves RSA y secretos en HashiCorp Vault durante el arranque del entorno Docker
│
├── server.js                  # Punto de entrada de la API
├── Dockerfile                 # Imagen Docker del backend
└── package.json
```

## APP-03: Servicio de Pagos (Microservicio)

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-payments` |
| **Tipo** | Microservicio REST |
| **Tecnología** | NestJS + TypeScript + TypeORM + BullMQ |
| **Puerto de desarrollo** | 3001 |
| **Responsabilidad** | Gestiona de forma autónoma el procesamiento de cobros al arrendatario, la retención de fondos durante el periodo de alquiler, la liberación al arrendador al finalizar y los reembolsos por cancelaciones. Mantiene un historial completo de transacciones con trazabilidad de estados. |
| **Comunicación** | Recibe solicitudes HTTP/HTTPS desde la aplicación web. Se integra con el Payment Gateway para procesar transacciones. Utiliza BullMQ sobre Redis como cola de trabajos para gestionar reintentos ante fallos del proveedor. Publica y consume eventos de estado en RabbitMQ. Obtiene credenciales desde HashiCorp Vault. |
| **Módulos cubiertos** | Gestión de Pagos, Reembolsos e Historial de Transacciones. |

**Estructura de directorios:**
```text
driveshare-payments/
├── src/
│   ├── payments/              # Módulo principal de pagos
│   │   ├── payments.controller.ts
│   │   ├── payments.service.ts
│   │   ├── payments.module.ts
│   │   └── payments.repository.ts
│   ├── queues/                # Configuración y procesadores de colas BullMQ
│   ├── integrations/          # Integración con servicios externos
│   │   ├── paymentGateway/    # Comunicación con el proveedor de pagos
│   │   └── vault/             # Obtención de credenciales desde HashiCorp Vault
│   ├── entities/              # Entidades TypeORM para transacciones y estados
│   ├── config/                # Configuración de la aplicación y conexiones
│   └── tests/                 # Pruebas unitarias e integración
│
├── main.ts                    # Punto de entrada del microservicio
├── Dockerfile
└── package.json
```

## APP-04: Base de Datos Principal

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-db` |
| **Tipo** | Base de datos relacional |
| **Tecnología** | PostgreSQL 15+ |
| **Puerto** | 5432 |
| **Responsabilidad** | Persistencia de la información de usuarios, vehículos, reservas y reseñas. Garantiza la integridad de los datos mediante claves primarias, claves foráneas, restricciones de unicidad y transacciones ACID. |
| **Comunicación** | Accedida únicamente por la API REST mediante Sequelize. No es accesible directamente desde el frontend ni desde el Servicio de Pagos. |

**Tablas principales:**

| Tabla | Módulo | Descripción |
| - | - | - |
| `users` | Usuarios | Información de arrendadores y arrendatarios, incluyendo autenticación local y mediante Google OAuth. |
| `vehicles` | Vehículos | Información de los vehículos publicados para alquiler, incluyendo características, ubicación, disponibilidad y precio. |
| `vehicle_images` | Vehículos | Referencias a las imágenes asociadas a cada vehículo almacenadas mediante MinIO. |
| `reservations` | Reservas | Registro de reservas realizadas por los usuarios, incluyendo fechas, estado y costo total del alquiler. |
| `reviews` | Reseñas | Calificaciones y comentarios realizados por los usuarios sobre los vehículos alquilados. |

**Relaciones principales:**

- Un usuario puede publicar múltiples vehículos.
- Un vehículo pertenece a un único propietario.
- Un vehículo puede tener múltiples imágenes asociadas.
- Un usuario puede realizar múltiples reservas.
- Cada reserva está asociada a un único vehículo.
- Las reseñas están asociadas a una reserva, un usuario y un vehículo.

## APP-05: Base de Datos de Pagos

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-payments-db` |
| **Tipo** | Base de datos relacional |
| **Tecnología** | PostgreSQL 15+ |
| **Puerto** | 5433 |
| **Responsabilidad** | Persistencia exclusiva de las transacciones financieras del Servicio de Pagos. Almacena cobros, retenciones, liberaciones, reembolsos e historial de estados de pago con trazabilidad completa. |
| **Comunicación** | Accedida únicamente por el Servicio de Pagos mediante TypeORM. Aislada del resto de la plataforma para proteger los datos financieros. |

**Tablas principales:**

| Tabla | Descripción |
| - | - |
| `transactions` | Registro de cada operación de pago con su monto, estado y referencia a la reserva. |
| `transaction_states` | Historial de cambios de estado de cada transacción (pendiente, retenido, liberado, reembolsado). |
| `payment_methods` | Métodos de pago utilizados por cada arrendatario (tarjeta, Yape, Plin). |

## APP-07: Caché y Cola de Trabajos

| Atributo | Detalle |
| - | - |
| **Nombre** | `driveshare-cache` |
| **Tipo** | Almacenamiento en memoria |
| **Tecnología** | Redis |
| **Puerto** | 6379 |
| **Responsabilidad** | Almacena temporalmente disponibilidad de vehículos, sesiones de usuario y puntuaciones de reputación para optimizar el rendimiento de la API REST. Actúa además como backend de BullMQ para la cola de trabajos del Servicio de Pagos. |
| **Comunicación** | Accedido por la API REST para caché general y por el Servicio de Pagos para la gestión de la cola de trabajos BullMQ. |
