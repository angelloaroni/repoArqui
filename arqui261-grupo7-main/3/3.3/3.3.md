# 3.3. Consolidación de Escenarios

| ID Escenario | Atributo de Calidad | Estímulo | Respuesta | ID Escenario Preliminar | Sustento | Comentarios |
|--------------|---------------------|-----------|------------|-------------------------|----------|-------------|
| CONS-01 | Seguridad | Intento de acceso no autorizado a cuentas o credenciales de usuarios | El sistema protege las credenciales mediante cifrado, bloqueo temporal y validación de autenticidad | ESCP-01, ESCP-02 | Protección de identidad y acceso al sistema | Escenario crítico para autenticación |
| CONS-02 | Disponibilidad | Fallo de servicios asociados a autenticación y recuperación de cuentas | El sistema reintenta operaciones y mantiene la continuidad del acceso | ESCP-03, ESCP-06 | Disponibilidad del módulo de usuarios | Dependencia de servicios externos |
| CONS-03 | Usabilidad | Usuarios nuevos utilizan funcionalidades por primera vez | El sistema proporciona validaciones y asistencia contextual para completar tareas exitosamente | ESCP-04, ESCP-08, ESCP-10, ESCP-21, ESCP-38 | Experiencia inicial de usuario | Impacta adopción de la plataforma |
| CONS-04 | Rendimiento | Alta concurrencia en procesos de autenticación | El sistema procesa solicitudes simultáneas manteniendo tiempos aceptables de respuesta | ESCP-07 | Acceso concurrente de usuarios | Escenario frecuente en horas pico |
| CONS-05 | Seguridad | Intento de carga de contenido malicioso en la plataforma | El sistema valida y bloquea archivos potencialmente peligrosos | ESCP-13 | Protección del catálogo | Reduce riesgos de seguridad |
| CONS-06 | Rendimiento | Elevada cantidad de búsquedas y consultas simultáneas | El sistema mantiene tiempos de respuesta estables bajo carga | ESCP-11, ESCP-18, ESCP-35 | Operación intensiva del sistema | Impacta experiencia de usuario |
| CONS-07 | Escalabilidad | Incremento sostenido de publicaciones, reservas y transacciones | La infraestructura distribuye la carga sin degradar el servicio | ESCP-12, ESCP-23, ESCP-32 | Crecimiento esperado del negocio | Escenario estratégico |
| CONS-08 | Disponibilidad | Fallo parcial de componentes del catálogo o infraestructura | El sistema redirige solicitudes y mantiene el servicio disponible | ESCP-09, ESCP-16 | Continuidad operacional | Tolerancia a fallos |
| CONS-09 | Disponibilidad | Solicitudes concurrentes sobre la disponibilidad de vehículos | El sistema evita inconsistencias y mantiene sincronizada la disponibilidad | ESCP-17, ESCP-24 | Gestión correcta de reservas | Evita conflictos operativos |
| CONS-10 | Seguridad | Intento de modificar recursos o transacciones sin autorización | El sistema valida permisos y bloquea acciones no autorizadas | ESCP-19, ESCP-33, ESCP-34 | Integridad de operaciones y reputación | Protección de datos críticos |
| CONS-11 | Fiabilidad | Fallo durante la ejecución de una reserva | El sistema recupera la transacción sin pérdida ni duplicidad de información | ESCP-22 | Integridad transaccional | Alta criticidad |
| CONS-12 | Seguridad | Intentos de fraude o acceso indebido a información financiera | El sistema detecta actividades sospechosas y protege los datos sensibles | ESCP-26, ESCP-28 | Protección financiera | Riesgo económico alto |
| CONS-13 | Disponibilidad | Caída de servicios de pago o bases de datos financieras | El sistema mantiene consistencia y recupera el servicio sin afectar transacciones | ESCP-20, ESCP-29, ESCP-30 | Dependencia de proveedores externos | Crítico para el negocio |
| CONS-14 | Mantenibilidad | Evolución de algoritmos, integraciones o funcionalidades del sistema | El sistema permite modificaciones con bajo impacto en los demás componentes | ESCP-05, ESCP-14, ESCP-27, ESCP-31, ESCP-39 | Adaptabilidad del software | Facilita evolución futura |
| CONS-15 | Interoperabilidad | Intercambio de información entre módulos internos o servicios externos | El sistema sincroniza correctamente los datos requeridos para cada operación | ESCP-40 | Integración entre módulos | Dependencia arquitectónica |
