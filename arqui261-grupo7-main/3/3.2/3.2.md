# 3.2. Brainstorming de Escenarios

| ID | Stakeholder | Atributo de Calidad | Estímulo | Respuesta | Comentarios |
|----|------------|---------------------|-----------|-----------|-------------|
| ESCP-01 | STK-02 (Arquitecto) | Seguridad | Se expone accidentalmente la base de datos de credenciales de usuarios. | Las contraseñas permanecen cifradas y no pueden recuperarse en texto plano. | Riesgo alto por exposición de credenciales de usuarios |
| ESCP-02 | USR-02 (Arrendatario) | Seguridad | Un atacante realiza múltiples intentos fallidos de inicio de sesión. | El sistema bloquea temporalmente la cuenta y notifica al usuario. | Escenario crítico para proteger cuentas de usuarios |
| ESCP-03 | STK-09 (DevOps) | Disponibilidad | Se pierde temporalmente la conexión con la API de autenticación. | El sistema reintenta la conexión automáticamente manteniendo las sesiones activas. | Dependencia de conectividad externa |
| ESCP-04 | USR-01 (Propietario) | Usabilidad | Un nuevo usuario intenta registrarse desde un dispositivo móvil. | El sistema guía el proceso mediante validaciones y mensajes claros. | Impacta directamente la adquisición de nuevos usuarios |
| ESCP-05 | STK-07 (Desarrollador) | Mantenibilidad | Se requiere migrar el algoritmo de cifrado de contraseñas. | El sistema permite la migración sin afectar la operación normal. | Requiere compatibilidad con futuras actualizaciones de seguridad |
| ESCP-06 | STK-09 (DevOps) | Disponibilidad | El servicio de correo para recuperación de contraseña presenta fallas. | El sistema reintenta el envío y permite solicitar un nuevo correo. | Dependencia de proveedor externo de correo |
| ESCP-07 | USR-01 (Propietario) | Rendimiento | Mil usuarios intentan iniciar sesión simultáneamente. | El sistema procesa las autenticaciones sin degradación perceptible. | Crítico durante horas pico de uso |
| ESCP-08 | USR-02 (Arrendatario) | Usabilidad | Un usuario completa por primera vez su perfil. | La plataforma proporciona ayudas visuales y validaciones intuitivas. | Mejora la experiencia de incorporación de usuarios |
| ESCP-09 | USR-02 (Arrendatario) | Disponibilidad | Un usuario consulta vehículos durante temporada alta. | El sistema mantiene el servicio disponible incluso ante fallos parciales. | Escenario relevante en temporadas de alta demanda |
| ESCP-10 | USR-02 (Arrendatario) | Usabilidad | Un usuario utiliza los filtros de búsqueda por primera vez. | El sistema muestra filtros comprensibles y resultados relevantes. | Impacta la experiencia de búsqueda inicial |
| ESCP-11 | STK-09 (DevOps) | Rendimiento | Miles de consultas de búsqueda se ejecutan simultáneamente. | El sistema procesa las búsquedas sin rechazar solicitudes. | Requiere optimización para alta concurrencia |
| ESCP-12 | USR-01 (Propietario) | Escalabilidad | Aumenta significativamente la cantidad de vehículos publicados. | El sistema mantiene tiempos de respuesta estables. | Relacionado con crecimiento del negocio |
| ESCP-13 | STK-02 (Arquitecto) | Seguridad | Un usuario intenta cargar una imagen maliciosa al catálogo. | El sistema bloquea el archivo y registra el incidente. | Riesgo de carga de contenido malicioso |
| ESCP-14 | STK-07 (Desarrollador) | Mantenibilidad | Se detecta un error en el motor de búsqueda. | El sistema permite aplicar correcciones sin interrumpir el servicio. | Facilita la evolución continua del sistema |
| ESCP-15 | USR-01 (Propietario) | Rendimiento | Un propietario publica múltiples vehículos con imágenes simultáneamente. | El sistema procesa la carga sin afectar la experiencia de usuario. | Escenario frecuente para propietarios activos |
| ESCP-16 | STK-03 (Operador) | Disponibilidad | Un servidor del catálogo deja de responder. | El sistema redirige las solicitudes a instancias disponibles. | Requiere tolerancia ante fallos de infraestructura |
| ESCP-17 | USR-02 (Arrendatario) | Disponibilidad | Dos usuarios intentan reservar el mismo vehículo al mismo tiempo. | El sistema evita reservas duplicadas bloqueando la disponibilidad temporalmente. | Escenario crítico para evitar conflictos de reserva |
| ESCP-18 | USR-02 (Arrendatario) | Rendimiento | Quinientos usuarios consultan disponibilidad simultáneamente. | El sistema responde dentro de los tiempos establecidos. | Impacta directamente la experiencia de alquiler |
| ESCP-19 | STK-02 (Arquitecto) | Seguridad | Un usuario intenta modificar una reserva ajena. | El sistema valida permisos y rechaza la operación. | Protección de integridad de las reservas |
| ESCP-20 | USR-03 (Yape/Plin) | Disponibilidad | El pago asociado a una reserva demora en confirmarse. | La reserva permanece en estado pendiente hasta recibir confirmación. | Dependencia de servicios externos de pago |
| ESCP-21 | USR-02 (Arrendatario) | Usabilidad | Un usuario modifica las fechas de una reserva. | El sistema muestra conflictos y costos actualizados en tiempo real. | Mejora la flexibilidad para el arrendatario |
| ESCP-22 | STK-09 (DevOps) | Fiabilidad | El sistema falla durante la creación de una reserva. | La transacción se recupera sin pérdida ni duplicación de datos. | Crítico para la integridad transaccional |
| ESCP-23 | STK-02 (Arquitecto) | Escalabilidad | Se incrementa drásticamente la cantidad de reservas activas. | La infraestructura distribuye automáticamente la carga. | Relacionado con crecimiento estacional |
| ESCP-24 | USR-01 (Propietario) | Disponibilidad | Un propietario rechaza una solicitud de reserva. | La disponibilidad del vehículo se actualiza inmediatamente. | Requiere sincronización inmediata de disponibilidad |
| ESCP-25 | USR-02 (Arrendatario) | Rendimiento | Muchos usuarios completan pagos simultáneamente. | El sistema procesa las transacciones sin rechazar solicitudes. | Escenario crítico durante campañas o feriados |
| ESCP-26 | STK-02 (Arquitecto) | Seguridad | Se intenta realizar un pago utilizando una tarjeta robada. | El sistema bloquea la transacción sospechosa. | Riesgo financiero para la plataforma |
| ESCP-27 | STK-05 (Product Owner) | Mantenibilidad | La empresa decide cambiar de proveedor de pagos. | El sistema permite sustituir el adaptador sin modificar la lógica principal. | Facilita cambios estratégicos del negocio |
| ESCP-28 | STK-02 (Arquitecto) | Seguridad | Un atacante intenta acceder a datos de tarjetas almacenadas. | El sistema protege la información mediante tokenización y auditoría. | Protección de información financiera sensible |
| ESCP-29 | STK-09 (DevOps) | Disponibilidad | La base de datos de transacciones presenta una caída. | El sistema activa mecanismos de respaldo y recuperación. | Crítico para continuidad operativa |
| ESCP-30 | USR-03 (Yape/Plin) | Disponibilidad | El gateway de pagos deja de responder. | El sistema informa el error sin generar cobros inconsistentes. | Dependencia directa del proveedor de pagos |
| ESCP-31 | STK-07 (Desarrollador) | Mantenibilidad | Se requiere agregar un nuevo método de pago. | El sistema incorpora la funcionalidad sin afectar las existentes. | Facilita expansión de métodos de cobro |
| ESCP-32 | USR-08 (Inversionista) | Escalabilidad | El volumen de transacciones aumenta significativamente. | El sistema mantiene la estabilidad financiera y operativa. | Impacta la sostenibilidad del crecimiento |
| ESCP-33 | USR-09 (Comunidad de Usuarios) | Seguridad | Un usuario intenta publicar una reseña sin autenticarse. | El sistema rechaza la solicitud hasta validar la identidad. | Garantiza autenticidad de las reseñas |
| ESCP-34 | USR-09 (Comunidad de Usuarios) | Seguridad | Un usuario intenta reseñar una reserva inexistente. | El sistema verifica la reserva antes de aceptar la reseña. | Evita manipulación de reputaciones |
| ESCP-35 | USR-09 (Comunidad de Usuarios) | Rendimiento | Muchos usuarios consultan reputaciones simultáneamente. | El sistema mantiene tiempos de respuesta adecuados. | Escenario frecuente de consulta pública |
| ESCP-36 | USR-09 (Comunidad de Usuarios) | Rendimiento | Múltiples usuarios publican comentarios al mismo tiempo. | El sistema registra las reseñas sin conflictos ni pérdida de datos. | Mantiene consistencia de reputaciones |
| ESCP-37 | STK-09 (DevOps) | Disponibilidad | El servicio de reputación presenta una falla temporal. | El sistema recupera automáticamente el servicio. | Requiere recuperación automática del servicio |
| ESCP-38 | USR-01 (Propietario) | Usabilidad | Un usuario publica una reseña por primera vez. | El sistema presenta formularios claros y fáciles de completar. | Facilita participación de nuevos usuarios |
| ESCP-39 | STK-07 (Desarrollador) | Mantenibilidad | Se requiere agregar un nuevo criterio de reputación. | El sistema permite extender el modelo sin afectar otros módulos. | Favorece la evolución del sistema de reputación |
| ESCP-40 | STK-03 (Operador) | Interoperabilidad | El módulo de reputación necesita validar reservas finalizadas. | El sistema sincroniza correctamente la información entre módulos. | Dependencia entre módulos del sistema |
| ESCP-41 | STK-09 (DevOps) | Escalabilidad | La cantidad de usuarios registrados y solicitudes de inicio de sesión aumenta significativamente. | El sistema distribuye la carga de autenticación entre múltiples instancias manteniendo tiempos de respuesta estables. | Relacionado con el crecimiento de usuarios de la plataforma |
